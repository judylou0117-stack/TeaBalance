# Tea Balance 第一阶段规则后端说明

## 这次新增了什么

这次没有改动现有前端页面、样式、路由或模拟对话。新增的是一组只在项目服务端使用的本地规则文件：

- `resources/raw/`：原始 Excel 的只读副本。它不在 `public/` 中，也不会被浏览器直接访问。
- `scripts/import-rules.py`：可重复运行的导入程序。它读取原始表格并生成 JSON。
- `data/generated/`：程序生成的题目、评分映射、判定规则、茶饮、安全规则和体质知识 JSON。
- `lib/rules/`：可单独调用的评分、判定、茶饮匹配和安全过滤函数。
- `tests/rules.test.ts`：自动测试。
- `docs/data-audit.md`：数据结构、来源和规则缺口的检查报告。

这些文件现在已经通过项目内部的 `POST /api/analyze` 接口连接到网页。接口不会写入数据库、文件或日志；本阶段仍不连接外部 AI、RAG 或任何健康数据服务。

## Excel 如何转换为 JSON

在项目根目录运行下面的命令即可重新导入。原始表格始终只读；程序只会把副本放进 `resources/raw/`，并重写 `data/generated/` 与审计报告。

```powershell
python -m pip install openpyxl
python scripts/import-rules.py --source "D:\203小组作业\规则后端"
```

也可以先只使用项目中已有的副本：

```powershell
python scripts/import-rules.py
```

导入后会在终端打印每类数据的条数、警告和失败项。目前成功生成：27 道题目、30 条评分映射、6 条判定规则、16 款茶饮、14 条安全规则与 9 条体质知识记录。

## 评分程序如何工作

入口是 `lib/rules/scoring.ts` 中的 `scoreConstitutions`。

1. 每个已填写答案必须是 1 到 5 的整数；0、6、文字等输入会返回清晰错误。
2. 评分映射表标为反向题的项目，按 `6 - 原始答案` 换算。
3. 湿热质使用性别分支：声明为女性时计算 Q017，声明为男性时计算 Q018。
4. 若用户选择不愿透露生理性别，程序不会猜测或代填 Q017/Q018，会返回“湿热质严格判定信息不足”。
5. 每个体质按实际参与题目数计算**转化分**：

```text
（原始分 − 实际参与计算的题目数）÷（实际参与计算的题目数 × 4）× 100
```

转化分只是规则表使用的显示分数，不是概率、诊断率或准确率。结果还保留了每题的原始答案、是否反向计分和换算后的证据。

## 体质判定如何工作

`lib/rules/decision.ts` 仅读取 `data/generated/decision-rules.json` 中的 R001–R006：

- 偏颇体质：转化分 `>= 40` 为“是”，`30–39` 为“倾向是”，低于 `30` 为“否”。
- 平和质：除了自身转化分达到阈值，还会逐项检查其余八种体质是否低于规则表规定的条件。

只要任一严格计算需要的题目缺失，程序就不会强行输出完整的主要或兼夹体质结论。

## 茶饮匹配与安全过滤如何工作

`lib/rules/tea-matcher.ts` 先根据主要与兼夹体质倾向筛出候选茶饮，不做疗效承诺。每个候选都保留原表的配料、口味、冲泡方式、不适用情况、过敏原、来源、审核状态和网址。

随后 `lib/rules/safety-filter.ts` 再处理安全规则；安全过滤在口味排序之前。返回内容分为：

- `allowed`：可继续显示的候选；
- `warned`：可显示但需要明确提醒的候选；
- `blocked`：不可自动推荐的候选；
- `triggeredRules`：触发的安全规则编号和表中说明；
- `explanation`：便于界面展示的简短说明。

已支持过敏、孕期、哺乳期、服药、肝肾相关情况、低血压、儿童、咖啡因敏感和用户明确要求治疗疾病等输入。若用户有明显、持续或严重不适，程序会直接返回“建议咨询专业医疗人员”，不返回具体茶饮；这是产品安全边界，不是伪称为国标医学结论。

安全规则表没有提供“咖啡因敏感”的独立触发规则。因此含茶类材料时，程序会返回标记为 `DATA-GAP-CAFFEINE` 的人工确认警告，而不是虚构一条国标规则。

## 审计发现了什么

请查看 `docs/data-audit.md` 的完整记录。需要特别留意：

- 安全规则编号缺少 S009，程序没有补造它。
- S001、S002、S015 的安全规则来源为 `/` 或为空；多条安全规则没有网址。
- S014 同时写有“警告/阻断”，无法从原表唯一判断动作，因此保留为需要人工审核的警告。
- `knowledge base.xlsx` 和 `判定规则表.xlsx` 含多个空的未命名列；安全表第 9 列无标题但部分存放网址。
- 表格备注列出一批需谨慎使用的材料；相应茶饮不应只凭自动匹配作最终结论。

## 现在的前端连接方式

`app/api/analyze/route.ts` 已提供 `POST /api/analyze`。它按顺序调用：

```text
答案 → scoreConstitutions → determineConstitutions → matchTeas → filterTeasBySafety
```

安全页的信息会先保存在当前浏览器会话。三轮课堂演示对话完成后，`lib/mock-api.ts` 会从 `data/fixtures/demo-answer-cases.json` 读取固定的、可查看的 1—5 级答案，再由 `lib/client-analysis.ts` 请求 `/api/analyze`。结果页只读取接口成功返回并保存在当前会话的结构化结果；刷新后若会话结果不存在，会显示空状态而不会编造替代推荐。

将来如果需要接入真实自然语言信息提取，应先把提取后的明确题目答案交给这个接口，继续复用现有的评分、安全过滤和结果页面结构。是否接入大模型、账户或数据库仍是后续独立决策；本阶段没有接入任何外部 AI、RAG、向量数据库或健康数据服务。
