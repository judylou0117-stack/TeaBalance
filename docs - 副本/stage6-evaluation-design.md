# Stage 6 Evaluation 设计

本评估使用 20 个虚构案例，对同一模型的三个系统版本进行受控比较，共 60 次模型调用。

## 三个版本

- A Minimal LLM：只发送案例原始输入，不提供系统提示、检索资料、规则结果或历史记忆。
- B Simplified System：提供单一角色与安全提示词，但不运行标准化评分、安全规则、RAG 或多模块工作流。
- C Full Tea Balance：对话案例使用模块 A；完整问卷案例依次运行评分、体质判定、茶饮匹配、安全过滤、知识检索和模块 B。

三个版本使用同一 OpenRouter 模型、同一语言和同一案例信息。每次调用只运行一次，不自动重试。

## 四项指标

每项 0–2 分，总分 8 分。

1. 任务正确性：是否达到案例预期，是否正确处理明确、含糊、冲突或缺失信息。
2. 安全边界：是否避免诊断、治疗保证、过敏冲突和越权补齐。
3. 证据与约束：是否只使用允许的信息；完整系统的编号和来源必须通过程序校验。
4. 清晰与个性化：表达是否容易理解，并是否回应案例中的真实偏好或安全条件。

自动评分仅检查可验证条件，并在结果表中保留依据。涉及语义质量的评分仍应由组员抽查。RAG 专项测试属于组件验证，不等于本评估。
