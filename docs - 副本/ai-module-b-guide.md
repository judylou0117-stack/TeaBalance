# AI 模块 B：结果解释生成

## 它做什么

模块 B 在规则后端已经完成评分、体质倾向判定、茶饮安全过滤和知识检索之后，才负责把这些**已有结果**整理成更容易阅读的说明。它不参与评分，不修改体质判定，也不会增加一款规则与安全过滤没有保留的茶饮。

它的入口是 `POST /api/explanation`。请求体中的 `analysis` 必须是 `/api/analyze` 返回的完整结构化结果。

## 数据流

1. 前端完成课堂演示对话后，请求 `/api/analyze`。
2. `/api/analyze` 调用规则引擎与小型知识检索，得到转化分、体质倾向、允许茶饮、安全提醒和知识资料。
3. 结果页在用户点击“生成说明”后，把这份已经得到的分析结果提交给 `/api/explanation`。
4. 模块 B 只把必要的规则结果、允许茶饮、安全提醒与已检索知识传给模型。
5. 模型返回严格 JSON；服务端检查茶饮编号、知识编号、禁用表达和不允许的链接或用量。
6. 只有通过检查的说明才会显示。来源卡片则由系统根据知识编号和原始知识数据组装。

## 主要文件

- `lib/ai/explanation-prompt.ts`：正式提示词和模型输出 JSON 结构。
- `lib/ai/explanation-input.ts`：从规则分析结果提取模型所需的最小输入。
- `lib/ai/model-client.ts`：仅在服务端调用 OpenRouter Chat Completions API。
- `lib/ai/mock-model-client.ts`：确定性的课堂演示说明，不会发起任何模型请求。
- `lib/openrouter/client.ts`：模块 A/B 共用的 OpenRouter 请求、结构化输出和响应文本适配层。
- `lib/ai/explanation-validation.ts`：验证模型返回的茶饮编号、知识编号和内容边界。
- `lib/ai/explanation-service.ts`：处理未配置、超时、无效输出和成功结果；失败时保留原始规则结果、安全提醒和来源。
- `lib/ai/source-citations.ts`：由系统生成来源卡片，模型不能自行提供网址。
- `app/api/explanation/route.ts`：项目内部的模块 B 接口。
- `components/result/AiExplanationPanel.tsx`：结果页中的说明与来源卡片。

## 配置真实模型

默认是课堂演示模拟模式，因此不会发出真实模型请求，也不能把模拟测试当作真实调用成功。将模式显式切换到 `live` 但未补全配置时，模块 B 返回“未配置”，不会用模拟说明冒充真实生成。

若要在本机启用真实调用，请在项目根目录新建 `.env.local`（该文件已被 Git 忽略），填入：

```text
TEA_BALANCE_AI_MODE=live
OPENROUTER_API_KEY=你的服务端密钥
OPENROUTER_MODEL=经核实的 OpenRouter 模型 ID
# 或只配置模块 B：
OPENROUTER_MODEL_B=经核实的 OpenRouter 模型 ID
```

`OPENROUTER_MODEL_A` 可为模块 A 单独设置模型；未设置时它会使用 `OPENROUTER_MODEL`。不要把密钥放进 `NEXT_PUBLIC_` 变量、前端组件、提交记录或压缩包。部署时，应在托管平台的服务端环境变量设置相同字段，而不是上传 `.env.local`。

## 如何验证一次真实调用

1. 配置好 `.env.local` 后重新启动本地项目；确认模型页面支持结构化输出。
2. 从首页完成安全信息与三轮课堂演示对话，进入结果页。
3. 检查规则结果、安全提醒和知识来源先正常显示。
4. 点击“生成说明”。
5. 成功时会显示体质倾向说明、匹配证据、茶饮推荐理由，以及由系统组装的来源卡片。
6. 如果超时、密钥缺失或输出不合格，页面会显示明确状态；不会伪造说明，也不会覆盖规则结果。

## 当前限制

- 模块 A 默认仍是课堂演示模拟；真实模式下，它只负责提出待确认候选答案。
- 检索是基于本地 JSON 的小型文本检索，不是向量数据库。
- `review_status=verified` 仅代表组员表格中的填写状态，不能替代真实来源核验。
- 模块 B 的输出是日常参考说明，不提供医学诊断或治疗建议。

## AI 模块 A 的下一步

模块 A 应只负责自然语言对话和信息提取。它应输出可确认的题目答案，例如 `Q001: 1–5`、提取依据和不确定项；用户确认后再提交给 `/api/analyze`。模块 A 不应直接计算转化分、判定体质、推荐茶饮或绕过安全过滤。这样模块 B 仍可读取同一份 `/api/analyze` 结果，无需改变评分、安全和检索模块。

## 测试

`tests/explanation-service.test.ts` 覆盖：正常解释、没有可推荐茶饮、知识不足、无效引用、模型超时，以及模型试图添加未允许茶饮。全套规则、接口、知识检索与模块 B 测试通过后，才应进行人工的真实模型调用检查。
